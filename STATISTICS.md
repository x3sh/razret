# Статистика качества Razret

Сбор добровольный, по умолчанию выключен. При первом запуске версии со статистикой приложение спрашивает согласие; настройка «Отправлять статистику качества» сохраняется сразу. Отказ не ограничивает работу приложения. Выключение удаляет локальную очередь и отменяет текущую отправку. Уже полученные обезличенные сводки нельзя связать с конкретной установкой.

## Что передаётся

- Версии Razret и zapret и календарный день UTC без точного времени.
- Название опубликованной стратегии; счётчики успешных и неудачных проверок, отдельно Discord, YouTube и запуск стратегии.
- Категория технической ошибки из фиксированного списка, без сообщения и журнала.
- Итог скачивания/установки обновления и версия, которую устанавливали.
- Случайный номер одного отчёта для защиты от повторного подсчёта при повторной отправке. Для каждого нового отчёта он новый; постоянного идентификатора установки нет.

Не передаются включения/выключения, время запуска приложения, сессии, длительность использования, имя пользователя или компьютера, оборудование, личные файлы, адреса сайтов, переписка и содержимое трафика. IP не входит в отчёт и не хранится в базе статистики. Сервер и хостинг неизбежно видят адрес доставки; сервер использует его хэш только для кратковременного ограничения запросов в памяти процесса. Инфраструктурные журналы хостинга имеют собственную политику хранения.

## Доставка и ограничения

Сводки сохраняются в `data/statistics.json` и отправляются в фоне после завершения проверки/операции, затем при необходимости раз в 10 минут, пока приложение работает. Пустые отчёты и события запуска не отправляются. До закрытия для установки обновления приложение пробует отправить уже накопленный отчёт. Неудачная доставка повторяется с тем же номером и содержимым. Очередь ограничена 30 отчётами и 30 днями, счётчик каждой метрики — 10000. Отсутствие сервера не мешает обходу. Отмена операции не считается ошибкой.

Панель показывает агрегаты за последние 30 дней, без ленты отдельных действий и списка людей. Количество отчётов не равно количеству пользователей. Процент успеха характеризует автоматические пробы; он не гарантирует доступность голосовых звонков. Статистика основана на добровольных самоотчётах, её можно исказить; это не биллинг и не достоверный подсчёт аудитории.

## Сервер

Исходники в `statistics-server`. На Vercel: проект `razret-statistics`, закрытое хранилище Blob `razret-quality-reports`, регион `fra1`. `/api/collect` доступен приложению без входа; он принимает только строгий ограниченный JSON. `/api/summary` требует сессии разработчика. Пароль проверяется по SHA-256; сессия подписана отдельным секретом, cookie HttpOnly/Secure/SameSite=Strict, срок 8 часов. Пароли и секреты находятся только в переменных окружения и локальной игнорируемой папке `research`, никогда в сборке приложения или GitHub.

Сырые сводки удаляются ежедневной задачей после 90 дней. Панель также чистит истёкшие отчёты. При превышении 5000 отчётов панель сообщает о неполной сводке; перед ростом объёма следует перейти на базу данных. Размер запроса ограничен 32 KiB, отчёт — 100 метриками. Ограничение частоты в памяти процесса дополняет защиту хостинга и не заменяет глобальные правила защиты от злоупотреблений.

Локально: `npm ci`, `npm test`, `npm run build`; для предпросмотра задайте `RAZRET_LOCAL_DATA`, `ADMIN_PASSWORD_HASH` и `SESSION_SECRET`, затем `npm run dev`. Локальное файловое хранилище применяется только вне production. Продакшен использует OIDC-доступ Vercel Blob. Секреты: `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `CRON_SECRET`. Повторное размещение: из `statistics-server` через привязанный проект Vercel. Новая версия приложения проверяется и публикуется отдельно через GitHub Releases.

Проверки приложения: `--statistics-test` (согласие, безопасные поля, агрегация, повторные запросы, отказ и отмена), `--self-test`, `--ui-test`. Серверные проверки: `npm test` (отсечение личных полей, повторная доставка, доступ к сводке, авторизация).
